# 五人平等分工与集成约定

姓名、学号和已完成贡献由实际成员填写。不要把 AI 生成的模块直接填写成未经理解和验证的个人成果。课程登记仍需一位组长；组长负责组织，不代替其他成员技术工作。

| 成员 | 主责与代码目录 | 独立验收 | 交叉检查 |
| --- | --- | --- | --- |
| 1 号：仿真与通信 | server/main.cpp、脚本、协议 | 编译、接口、地图同步、断线恢复 | 复核手机网络和错误状态 |
| 2 号：调度与寻路 | server/world.hpp、核心测试、实验 | 解释代价矩阵、A*、预约和真实策略数据 | 复核 MATLAB 动态障碍占位 |
| 3 号：MATLAB | clients/matlab | MATLAB 本机运行、四转弯测试、真实接送 | 复核服务端指令/状态同步 |
| 4 号：Android | clients/android、PoseEstimatorTest | 生成 APK、传感器状态、移动与 GNSS 实测 | 复核网页手机位姿和超时 |
| 5 号：3D 与展示 | web、演示证据、讲解材料 | 桌面/手机布局、3D/2D、录像和导出 | 复核两策略实验可复现 |

每人分别维护自己的测试记录、设计说明和报告章节；全员共同确认 API，轮流主持联调，至少能解释自己的模块如何影响其他模块。

## 分布式开发

- 分支建议：`feature/server`、`feature/scheduling`、`feature/matlab`、`feature/android`、`feature/visualization`。
- 改动公共 API 先同步 API.md；保持老字段含义或同时修改两端。
- 每个 PR 至少由相邻接口模块的一名同学审查，并附实际验证结果。
- 合并前通过核心和 HTTP 测试；手机变更还应构建 APK 并在指定真机测试。
- `experiments/` 中的结果只能由脚本生成，报告使用同一份结果，不能手工改成更好的数字。

## 课程节点

第 8 周：五车、订单和地图跑通；统一接口；MATLAB/手机各完成一条真实网络连接。

第 16 周：全模块连续运行、策略对比、3D 展示、报告、正文不超过五页的介绍 PPT 和总长建议不超过五分钟的视频。具体课程日期以老师安排为准，周次来自附件，不按当前日期杜撰日程。
